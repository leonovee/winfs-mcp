### 7. Claude Desktop probes — deferred (covered by Inspector + invariant tests)

In v0.1.0 → v0.1.1 the `structuredContent` wrapper failure was
*invisible* to Inspector (warning only) but presented as fake
`EPERM_ROOT` through Claude Desktop's strict client-side validation.
That failure mode is what made Claude Desktop probes a separate
acceptance criterion for v0.1.

In v0.2 the wrapper is the same as v0.1.1 (`src/core/tool_wrapper.ts`,
unchanged this version). The structuredContent invariant test
(`tests/invariants/structured_content.test.ts`) pins pure-payload
shape for all 10 tools including the 5 new ones. Inspector §6 above
demonstrated clean schema validation across every v0.2 tool surface.

The functional risk Claude Desktop probes would catch — wrapper
regression — is therefore covered by Inspector + unit tests. The
residual value of Claude Desktop probes is LLM-side UX validation
(tool-selection heuristics on new tool names, summary rendering of
mixed `read_multiple_files` output). Those are UX concerns, not
correctness, and can be tuned reactively if real-world use surfaces a
mismatch.

**Decision:** Claude Desktop probes for v0.2 are not run as a formal
acceptance step. v0.2.0 stamps on §1–§6 + §8. The five canonical
probes from the v0.2 prompt remain documented for future regression
runs but are not blocking.

## Hard invariants reaffirmed in v0.2

All 12 spec §2 invariants from v0.1 still hold. v0.2 adds two more:

- **Both-roots check for mutation tools.** `move` and `copy` must verify
  *both* `src` and `dst` resolve inside `allowedRoots` (pinned by
  `tests/invariants/both_roots.test.ts`).
- **Recursive copy does not follow symlinks outside allowedRoots.** Each
  walked entry is realpath-checked; escapes are skipped and surfaced
  in `files_skipped` + `skipped_paths` (cap 10).

## Open questions for v0.3

- **Cross-volume `move` with opt-in fallback.** Add `allow_cross_volume:
  boolean` argument that, when true, performs `copy + delete` and
  documents that the operation is no longer atomic. Tests would need to
  fake an EXDEV via mock fs or a real second drive.
- **`copy` symlink-skip telemetry.** If a tree has > 10 skipped paths
  the audit log should still record the total count even though the
  response is capped. (Currently the response is the source of truth;
  may evolve.)
- **`read_multiple_files` aggregate surface — spec amendment.** Spec
  §4.3 declares `Output: Array<...>`. v0.2 implementation returns
  `{files, total, ok_count, error_count}`. Formalize the envelope in a
  spec amendment so future tool authors don't have to reverse-engineer
  the v0.2 schema as the de-facto contract.
