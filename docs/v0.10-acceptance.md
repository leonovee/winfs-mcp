### v0.10.0 — child-spawn hardening + transport logging

- **Explicit PATHEXT on every spawn** — winfs pins a `STANDARD_WINDOWS_PATHEXT`
  on every spawn env rather than forwarding the inherited one (observed mangled
  to `.CPL` under Claude Desktop, which broke bare-name resolution of
  `git`/`node`/`where`/`taskkill`). Applied to `buildExecEnv`, `spawnGit`, the
  internal `taskkill` spawns, and the `where pwsh` probe.
- **`GIT_TERMINAL_PROMPT=0`** on git spawns and in `buildExecEnv` so an
  authenticated git op can't hang on a credential prompt.
- **`execute_command` shell-timeout pair** — `shellTimeoutMs` (30 s) /
  `shellMaxTimeoutMs` (300 s) instead of the general 10 s / 60 s pair; per-call
  `timeout_ms` honoured, clamped to the shell max. Config gate:
  `shellMaxTimeoutMs >= shellTimeoutMs`.
- **`allowedRoots` hot-reload** — edit the config file and the new roots take
  effect without a restart, via a debounced directory watch that survives
  atomic-replace writes. **Validate-before-apply**: a malformed edit keeps the
  previous config (the server never bricks); roots update only through
  `RootsResolver`, preserving the MCP-Roots union. Only `allowedRoots`
  hot-reloads.
- **`WINFS_TRANSPORT_LOG` — opt-in transport metadata logging** (#3
  investigation). Off by default; metadata-only (timestamp, id, method, byte
  count, status, duration — never bodies, contents, or secrets).

### v0.10.1 — final polish

- **Timeout-ceiling fix (HIGH)** — `runTool`'s OUTER timeout clamped every tool
  to `maxTimeoutMs` regardless of the per-call `timeout_ms`; long
  `execute_command`/`run_python`/`run_pytest`/`ssh_exec` calls died at ~10 s. The
  outer/inner deadlines are now coordinated so the graceful inner timeout fires
  first; a 6–8 min build is runnable.
- **`shellMaxTimeoutMs` default 300000 → 600000** (10 min) for long builds.
- **`ssh_exec` binary auto-detect** — `sshExePath` is now optional; when unset,
  `resolveSshBin` prefers the Git-bundled ssh over the often-broken System32
  client, then PATH.
- **`execExtraPathDirs`** (default `[]`) — extra absolute dirs appended to the
  sanitized subprocess PATH for non-standard tool installs.
- **`grep` P2.7** — single very long line capped at 4096 chars in stored
  match/context (memory-pressure DoS), with a surrogate-safe truncation marker.

## Key invariants added

- **#43** — every child spawn pins the standard Windows PATHEXT explicitly; the
  inherited (possibly mangled) PATHEXT is never trusted for bare-name resolution.
- **#44** — for the long-running exec tools the outer (`runTool` withTimeout) and
  inner (spawn) deadlines are coordinated so the inner graceful timeout fires
  first; the per-call `timeout_ms` is honoured up to the tool's own ceiling, not
  clamped to the general 60 s max.
