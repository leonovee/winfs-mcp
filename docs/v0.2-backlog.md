## Bugs found during v0.1 acceptance

### ~~#1 — `structuredContent` validation mismatch on every tool response~~ — RESOLVED in v0.1.1

**Status:** Fixed in v0.1.1 hotfix (Option B applied). See [`CHANGELOG.md`](../CHANGELOG.md) `[0.1.1]`. Invariant pinned by `tests/invariants/structured_content.test.ts`.

**Discovered:** 2026-05-16, during Inspector smoke test (acceptance #3).

**Symptom:** Inspector flags `Validation Error: data should NOT have additional properties` on every tool response. Server returns `ok`, `tool`, `error`, `hint` in `structuredContent`, but each tool's declared `outputSchema` lists only the success-payload fields (e.g., `stat` declares `{exists, is_dir?, size?, mtime?, ctime?, mode?}`; `list` declares `{entries, total}` with `additionalProperties: false`).

**Severity:** Escalated from cosmetic warning to **release blocker** on 2026-05-16: Claude Desktop marks every successful tool call as failed because of the envelope mismatch, while the audit log at `%LOCALAPPDATA%\mcp-winfs\audit.jsonl` shows `result_status: "ok"` for the same calls. v0.1.1 hotfix landed before re-running the Claude Desktop probe.

**Root cause:** Tool handlers wrap pure payload in a service envelope (`{ok, tool, ...payload, hint?}`) and emit the envelope as `structuredContent`. MCP spec convention: `structuredContent` should match `outputSchema` one-to-one, and service-level metadata (status, error envelope) belongs in `content` (text block) + `isError` flag — not in `structuredContent`.

**Fix (recommended — Option B from cc-report):**

Stop wrapping in `structuredContent`. Behavior per branch:

- **Success path:** `structuredContent` = pure payload matching the declared `outputSchema` exactly. Mirror as JSON in a text `content` block for clients that don't parse structured content. No `ok`/`tool`/`hint` fields.
- **Error path:** Omit `structuredContent` entirely. Emit error as `content: [{type: "text", text: JSON.stringify({code, message, details?, hint?})}]` plus `isError: true`. `outputSchema` is not validated on error responses (per MCP spec).

**Alternative rejected (Option A):** Adding `ok`, `tool`, `hint`, `error` to every `outputSchema` and removing `additionalProperties: false`. Discarded because it pollutes the schema with service metadata, making each tool's contract less clear for consumers.

**Test plan:**
- Update each tool handler in `src/tools/fs/*.ts` to emit pure payload in `structuredContent` on success, no `structuredContent` on error.
- Add invariant test: `tests/invariants/structured_content.test.ts` — for every tool, success response has `structuredContent` matching `outputSchema` exactly (validate with the same Zod schema); error response has no `structuredContent` field, only `content[0].text` containing the error JSON and `isError: true`.
- Re-run Inspector smoke: validation warnings should disappear on all 5 tools.

**Files to touch:** `src/tools/fs/{read,write,append,list,stat}.ts`, possibly `src/core/errors.ts` (if the envelope is built there), new `tests/invariants/structured_content.test.ts`.

**Estimate:** 30–60 minutes.
