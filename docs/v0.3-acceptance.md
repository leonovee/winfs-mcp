## Scope

v0.3 closes spec §7 row "Search & Convenience + `audit_tail`" — Claude can
explore the codebase without dropping to a shell and can recover from a
context loss by tailing the audit log.

4 new tools:

- `glob` — find files matching an absolute glob (`*`, `?`, `**`, `[...]`)
- `grep` — regex search across glob with context lines + partial-on-timeout
- `read_json` — read + parse with distinct `EBADJSON` code
- `audit_tail` — privileged tail of the structured audit log

3 carryover items from v0.2 also closed (see `docs/v0.2-backlog.md` strikethroughs).

### 6. Carryover items closed ✅

#### Carryover #1 — Cross-volume `move` opt-in fallback

`src/tools/fs/move.ts:23-26` — new arg `allow_cross_volume:boolean`
(default `false`). On EXDEV with the flag set, delegates to
`copyImpl(src, dst, {recursive:true})` followed by `fs.rm(src, {recursive:true})`.
Response envelope extended with `atomic:boolean` so callers can audit
which moves were race-free (atomic `fs.rename`) vs. non-atomic (copy+delete).

Tested via mocked `fs.rename` that always throws EXDEV — single-volume
test environments don't reproduce the errno deterministically.

#### Carryover #2 — `copy` symlink-skip telemetry to audit

Mechanism: new `ToolContext.auditExtras?: (result) => Record<string, unknown>`
hook in `src/core/tool_wrapper.ts`. Called after the impl resolves; merged
into `args_summary` on the audit record. `copy` uses a `WeakMap` keyed
by the result object to surface the un-capped `files_skipped_total` to
the audit hook without polluting the user-facing payload. User-facing
`skipped_paths` array remains capped at 10.

Tested in `tests/unit/fs/copy.test.ts` "records full files_skipped_total
for audit when skipped_paths is capped at 10" (15 escape-symlinks).

#### Carryover #3 — `read_multiple_files` envelope spec amendment

Spec amendment `2026-05-16 — v0.3 envelopes + move cross-volume opt-in
+ copy audit telemetry`, point §F: formalises the envelope shape for
every array-output tool. Extended beyond just `read_multiple_files` to
cover the v0.3 additions (`glob`, `grep`, `audit_tail`) so future tool
authors don't have to reverse-engineer the convention. Doc-only change.

## Hard invariants reaffirmed in v0.3

All v0.1 + v0.2 invariants (14 total: 12 from spec §2 + 2 from v0.2)
still hold. v0.3 adds five more:

- **Bounded execution for search tools.** `grep` owns its deadline and
  returns partial results with `reason:"timeout"` rather than synthesising
  an error. `glob` and `grep` walk only files realpath-checked against
  allowedRoots.
- **Regex compiled in sandbox.** `new RegExp(pattern, flags)` only — no
  `eval`, no `Function`. Malformed regex → `EINVAL` with the parser
  message; never throws.
- **Distinct `EBADJSON`.** Parse failures get their own code so callers
  can branch on parse-vs-IO failure without inspecting messages.
- **Privileged-read audit log exception is narrowly shape-gated.**
  `audit_tail` is the only tool that legitimately reads outside
  `allowedRoots`; the configured `auditLogPath` must end in `.jsonl` AND
  live inside a directory named `mcp-winfs`. Anything else →
  `EPERM_ROOT`.
- **Audit log gets full skip count on `copy`.** Even when the user-facing
  `skipped_paths` array is capped, the audit `args_summary` carries the
  un-capped `files_skipped_total` for telemetry.

## Open questions for v0.4

- **`edit_file` with `dry_run`.** Spec §4.4 already defines the surface.
  Confirm `unified diff` output format (V8 vs `diff` package).
- **`read_section` semantics on absent `end_marker`.** Spec says "до
  следующего того же уровня (для md) или EOF" — need to nail down what
  "следующего того же уровня" means in `marker_type: "regex"` mode (it
  doesn't generalise from headings).
- **`grep` regex flags surface beyond `case_sensitive`.** v0.3 ships
  `case_sensitive` only; multiline/dotall remain reachable via inline
  `(?m)` / `(?s)` in the pattern. Add a real `multiline:boolean` arg in
  v0.4 if Claude UX surfaces a need.
