## Review questions — answer each with a severity-tagged finding

Q1 (output capture via & operator): Empirically observed: when composed = '& "C:\path\git.exe" status', stdout/stderr come back empty though the command executes. PowerShell -Command with & operator invokes a child process. stdio:['ignore','pipe','pipe'] should capture PowerShell's stdout, which should include the child's output when run via &. Analyze: does -NonInteractive affect pipe inheritance? Is there a PowerShell output buffering issue? Is windowsHide:true a factor? What is the actual root cause? Severity and fix recommendation.

Q2 (argument composition quoting hazard): args.join(' ') without quoting. Contract says caller bears quoting. But the field name 'args' implies spawn-style positional args. A path with spaces in args[] will break. Evaluate: should the impl add EINVAL guard for whitespace-containing args, or auto-quote with PowerShell single-quote escaping, or document more prominently? Current MAX_ARGS_LEN=64 entries * 2048 chars each means a huge unquoted string is possible. Severity and recommendation.

Q3 (blocklist bypass): Analyze these specific vectors:
  (a) EncodedCommand: command='powershell -EncodedCommand <base64 of Remove-Item -Recurse C:\>'  — base64 bypasses pattern match
  (b) PS aliases: rm -r C:\ — blocklist has "rm\s.*-rf" but not "rm\s.*-r\b" (short flag -r is NOT caught by -rf pattern)
  (c) Variable indirection: $x = 'Remove-Item'; & $x -Recurse C:\ — does "Remove-Item\s.*-Recurse" match with semicolon separation? The composed string contains 'Remove-Item' and '-Recurse' but with other chars between. Does .* in the regex span the full string? Answer: yes, .* matches anything including spaces and semicolons in a single line, so '$x = "Remove-Item"; & $x -Recurse C:\' would NOT match because the pattern 'Remove-Item\s.*-Recurse' requires Remove-Item to be immediately followed by whitespace then eventually -Recurse. In the indirection case 'Remove-Item' appears as a string literal in quotes, not as a command invocation — but the raw text still contains 'Remove-Item' followed by '-Recurse' later. Check if it matches.
  (d) Blocklist cache bug: cache key = extra.join('|||') only. If process has multiple ResolvedConfig instances with different DEFAULT_EXEC_BLOCKLIST (e.g., monkey-patched in tests), cached compiled patterns would be stale. How severe?
  (e) Is -EncodedCommand itself blocked? No pattern covers it.

Q4 (PATH sanitization — non-standard git): sanitizedPathDirs hardcodes 'C:\Program Files\Git\cmd'. Non-standard git installs: C:\Program Files (x86)\Git\cmd (32-bit), scoop (%USERPROFILE%\scoop\apps\git), choco (C:\ProgramData\chocolatey\bin), portable git. find_command returned found:false on operator machine. Is there a dynamic resolution option? What is the spec invariant gap?

Q5 (AbortSignal + process tree kill): Three sub-issues:
  (a) If abort fires before spawn() returns pid (child.pid === undefined), killTree is a no-op (early guard: if (pid === undefined) return). Child is alive but untracked — orphan risk.
  (b) timed_out flag set only by deadline path. onAbort does NOT set timedOut=true. Caller sees timed_out:false + exit_code:null — cannot distinguish abort from normal exit-null.
  (c) taskkill /T kills child tree only if processes share the same job object or parent chain. Start-Process with -PassThru inside the spawned PowerShell creates a detached process that escapes /T scope.

Q6 (hints omitted from audit): diagnoseHints result NOT stored in auditByResult. If stderr > 4KB and the cryptic marker appears after the 4KB cutoff, the audit record will miss it but the live response would have included the hint. Is this a gap? Severity?

Q7 (hint accuracy for 'Cannot run a document in the middle of a pipeline'): The actual PowerShell error "Cannot run a document in the middle of a pipeline" occurs when: (1) user passes a bare .ps1 script path to -Command, PowerShell tries to execute it as a document (file), and the pipeline context rejects this; or (2) PATHEXT and file association routing. The hint text says "PATHEXT or unusual file association" and suggests "Try invoking it via a different shell (cmd)". Given that this tool ONLY dispatches through PowerShell and never cmd.exe, the advice "try cmd" is inapplicable and potentially confusing. Evaluate accuracy and actionability of the hint.

Q8 (blocklist taskkill /F coverage): Pattern "taskkill\s.*\/F" blocks any taskkill call with /F anywhere in the composed string. This means a caller cannot do 'taskkill /IM process.exe /F' even if the intent is legitimate process management. Also: is the blocklist correct to block ALL taskkill /F usage given that the tool description says it's a mutation tool? Evaluate: is the pattern correctly scoped, and should it be narrowed (e.g., also require /T or /PID)?

Q9 (cwdCheck cast): Line: cwd = (cwdCheck as { realPath: string }).realPath. If checkAllowed's success return type has a different shape (e.g., { ok: true, realPath: string } or just a string), the cast may silently produce undefined. This is a TypeScript-unsafety concern. Evaluate risk.
